Apna Clinic — backend API reference

Draft specification for backend teams. Paths below use {baseUrl} from app flavor (FlavorConfig.apiBaseUrl). The mobile client expects JSON with a top-level success boolean and usually message; many payloads live under data or feature-specific keys. Authenticated calls use Authorization: Bearer <token> unless noted.

Conventions Auth & session Dashboard & CMS Profile & user Notifications Search Pharmacy Lab tests Surgery Doctor consultation Bookings & orders Payments Support & content Admin & ops (optional)

Conventions

  • Content-Type: application/json
  • Errors: HTTP status + JSON body with success: false and human-readable message
  • Versioning: Prefer a prefix such as /api/v1 for new routes; the app currently mixes root paths and one versioned OTP path (see Auth).
  • Idempotency: POST for payments and booking confirmations should support idempotency keys where duplicates are costly.
{
  "success": true,
  "message": "OK",
  "data": { }
}

Auth & session

Implemented or partially referenced in lib/core/network/app_urls.dart and auth_remote_data_source_impl.dart.

API Method Path (relative to base) Usage
Generate OTP POST /api/v1.0/user-auth/auth/otp/generate Body: { "msisdn": "92…", "channel": "sms"|… }. Response drives OTP expiry and attempt counts (see AuthResponseModel).
Verify OTP POST /verify-otp full URL Body: { "phone": "…", "otp": "…" }. On success return token, user id, profile fields, isOnboardingCompleted.
Login (legacy) POST /login Reserved / alternate auth; align with product before implementing.
Sign-in variant POST /login_ww Placeholder path in app; document real contract if used.
Refresh token POST /refresh Return new access (and refresh) token; client updates stored bearer token.
Logout POST /logout Invalidate refresh token / session server-side; client clears local token.
Register device (FCM) POST /api/v1/users/me/devices proposed Body: { "fcmToken", "platform", "appVersion" } for push notifications.
Social token exchange POST /api/v1/auth/social/google etc. proposed If you add Google/Facebook sign-in beyond current OTP flow.
