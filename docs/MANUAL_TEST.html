How to use this report

Tick a use case when the expected result happens on a real device (or simulator where noted). Progress is saved in this browser.

Guest = not logged in Logged in = OTP done + profile saved Needs real device (camera / mic / push) Known gap / not in app

Before you start

  1. Use a test MSISDN that can receive OTP.
  2. Have a JazzCash test number and a card that can open the payment WebView.
  3. Fresh install (or clear app data) for first-launch cases.
  4. Push / Instant Doctor video: use a physical device.
  5. Do guest cases first, then login, then full bookings.

Login required vs guest OK

Guest can doNeeds login
Onboarding, home, browse services, search, support, FAQ, terms, FikrFree banner, lab/pharmacy/surgery browse, consultation categories Instant Doctor tab, My Bookings tab, notifications inbox, cart / add-to-cart, book doctor, AI screening, lab/pharmacy/surgery checkout, profile edit, add JazzCash account, logout

1. Splash, onboarding, guest home

Cold start decides: incomplete profile → setup · first launch → onboarding · else home.

2. Login, OTP, logout

Phone → OTP → session Resend timer from API (seconds) Terms / Privacy open in browser

3. Profile setup and Profile screen

First save: name, gender, optional email, address, DOB, optional photo. Email empty is OK; if filled it must contain @.

4. Home, banners, menu, app update

5. Global search (text + voice)

Search runs on submit (icon, keyboard, chip, or voice) — not while typing. Popular chips load when the field is empty.

6. Instant Doctor

Login required Subscribe OTP · Unsubscribe OTP Own video WebView (not card payment WebView)

7. Doctor consultation

Hub → category → doctor list (search/filter) → book (slot + issue + files) → checkout → summary → JazzCash or card.

8. Pharmacy

Browse is guest-OK. Cart, add-to-cart, and checkout need login. Rx products must upload a file (PNG/JPEG/WEBP/PDF, max 5 MB) before add.

9. Lab tests

City is required. First visit opens city picker. Saved city is remembered. Changing city / method / partner / lab with items in cart warns you.

10. Surgery

This flow creates a lead first. Payment is later from Bookings → Surgery → Proceed Checkout (when paymentAllowed).

11. My Bookings (all five tabs)

Inner tabs in order: Instant Doctor · Pharmacy · Doctor Consultation · Lab Tests · Surgery. Empty states have a CTA into that service.

12. Shared card payment WebView

Used by consultation, lab, pharmacy, surgery. Not Instant Doctor.

13. Notifications (inbox + push)

Push: physical device Guest: no inbox API, no booking deep links

14. Customer support

15. JazzCash linked phones

Used on Profile and in JazzCash pickers (consultation, lab, surgery, pharmacy).

16. Cross-cutting (do these once)

Worth raising if you still cannot do it

If a case below fails, it is a real gap (product or backend), not “not built on purpose”.

  • Cannot complete a full paid booking in each of: Instant Doctor, Consultation, Pharmacy, Lab, Surgery lead + pay.
  • Search result for a module does not open the same screen as browsing that module.
  • After login from a guest action, you always land on Home instead of the service/tab you wanted.
  • Push tap for CONSULTATION / SURGERY / LAB / PHARMACY does not open the matching details.
  • Home services grid missing a tile that CMS returns (or showing a tile CMS turned off).
  • Urdu device still shows large hardcoded English on a user-facing screen.
  • Card success is recorded when the user only opened the callback page or pressed X.
