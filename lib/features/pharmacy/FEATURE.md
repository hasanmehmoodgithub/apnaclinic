# Pharmacy feature

## Purpose

Browse medicines, cart, checkout, and view pharmacy order details. Each city is served by one pharmacy partner (MedIQ / Servaid); the app asks for a city, persists it, and sends `x-pharmacy-city-id` on every aggregator request so catalog, cart, and orders are partner-scoped. Pharmacy home has a **Scan prescription** button that reads a photo and lets matching catalog medicines be added to the cart. While reading, the photo shows a scan-line overlay (`PrescriptionScanOverlay`) instead of a spinner.

Mini-cart badge shows `99+` when total quantity is greater than 99.

## Multi-partner city routing

- **Cities API:** `GET` `AppUrls.pharmacyCities` → `…/mobile/partner/pharmacy/cities` → `{ id, name, slug, partner }[]` (only partner-served cities). Do **not** use the general `CitiesRepository` list.
- **Header:** `HeaderInterceptor` sends `x-pharmacy-city-id` from `AppPref.getPharmacyCityId()` on every mobile backend request once stored. Not part of HMAC. Absent header → MedIQ everywhere (old builds).
- **Storage:** `AppPref` `getPharmacyCity` / `setPharmacyCity` / `clearPharmacyCity` / `getPharmacyCityId` — `{ id, name, partner }`; kept across logout.
- **Picker:** `PharmacyMainScreen` syncs cities on open; required non-dismissible picker when no city (back exits pharmacy). Pill “Delivering to {city}” opens dismissible picker. Confirm reloads products + cart and clears search/product detail. Optional cart-switch hint when cart has items. Global search pharmacy result taps also require a city: if none is stored, the same picker opens before product detail (`reloadCatalog: false`).
- **Errors:** `PHARMACY_CITY_NOT_SERVED` / `PHARMACY_CITY_INVALID` → clear stored city and re-prompt. Product detail `404` → “Not available in {city}” + Change city. Checkout `PHARMACY_CITY_MISMATCH` (409) → show API message. Checkout `CART_ITEMS_INVALID` (`data.errorCode` + `failedItems`) → list items (price changed / out of stock) and allow remove, then reload cart.
- **Checkout city:** Locked to the stored pharmacy city (not the general cities list). Saved addresses filtered to that city.

## Data & APIs

| Action | Method | `AppUrls` | Body |
|--------|--------|-----------|------|
| Pharmacy cities | GET | `pharmacyCities` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cities` | — |
| List products | POST | `pharmacyProducts` → `acs-aggregator/api/v1/mobile/partner/pharmacy/products` | `{ "page": "1", "display_name": "" }` — pass search text in `display_name` when searching; empty for browse |
| Product detail | POST | `pharmacyProductDetail` → `acs-aggregator/api/v1/mobile/partner/pharmacy/product/details` | `{ "product_id": <id>, "similar_items": true }` — product fields in `data` (`product_id`, `display_name`, `image_url`, `price`, `manufacturer`, `category`, `prescription_required`, `generic_name`, `package_type`, `indications`, `contra_indications`, `images[]`); `data.similar_items[]` for “More like” (legacy `related_items` still parsed) |
| Cart (active) | POST | `pharmacyCart` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/active` | `{}` — cart in `data` or `data.data`: `products[]` / `items[]` (each may include `prescription_url`), `booking_id` / `booking.id`, `payment_breakdown` or root `subtotal` / `delivery_charges` / `discount` / `total`, `family_members[].addresses`, optional `failed_payment.unified_order_id` |
| Add to cart | POST | `pharmacyAddToCart` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/add` | `{ "product_id": <id>, "quantity": <n> }` — both **int**; does **not** send `prescription_url` (upload is a separate API); on success, update local cart/`cartBookingId` from response (no active-cart refetch) |
| Prescription upload | POST multipart | `pharmacyPrescriptionUpload` → `…/pharmacy/prescription/upload` | Form fields: `product_id` (int) + `file` (PNG/JPEG/WEBP/PDF, max 5MB). Success `data.url` (also accepts `prescription_url` / `file_url`). Required before add-to-cart when `prescription_required` is true |
| Update cart qty | POST | `pharmacyUpdateCartQuantity` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/quantity/update` | `{ "product_id": <id>, "quantity": <n> }` — both **int**; `quantity: 0` removes the line. Success may return the full active cart (`items[]`, totals, optional `failed_payment`). On success, update local cart from response (no active-cart refetch) |
| Order checkout | POST | `pharmacyOrderCheckout` → `…/pharmacy/order/checkout` | JSON `{ "user_location_id", "payment_method" (from payment-provider `code`), "prescriptions": [{ "product_id": number, "url": string }], optional `jazz_cash_number`, `delivery_instructions`, `name`, `promo_code` }` via `PharmacyCheckoutParams`; `user_location_id` from saved/created address id; `prescriptions` from cart `prescriptionUrl`s. Success `data.unified_order_id` is shown on the order-placed dialog (not UUID `order_id`). If `status` is `PENDING_PAYMENT` and `paymentUrl` is null, skip the card WebView and show `PaymentPendingDialogWidget` (then clear cart). If `paymentUrl` is present, open `settleCardPaymentIfNeeded` before the order-placed dialog. |
| Payment providers | GET | `paymentProviders(module: pharmacy)` → `/api/v2/mobile/payment-provider?module=pharmacy` | Checkout loads providers via `GetPaymentProvidersUseCase` and shows **only** API rows (no local **Pay via Cash**). Tiles show `title` + `label.text` chip (`label.color` bg), `subtitle`, and `termsAndCondition.title` + info icon (`description` as URL or dialog). Loading uses payment-row shimmers. |
| Order abandon | POST | `pharmacyOrderAbandon` → `…/pharmacy/order/abandon` | JSON `{ "unified_order_id": int }` from cart `failed_payment.unified_order_id` (load cart first if missing; send `0` when still null). Releases cart after unpaid/failed card checkout. Called from cart/add-to-cart error dialog CTA when payment-lock message is returned |
| List addresses | POST | `pharmacyProfileAddressesList` → `…/pharmacy/profile/addresses/list` | `{}` — `data[]`: `address_id`, `label`, `recipient_name`, `recipient_phone`, `line1`, `line2`, `city_id`, `city_name`, `latitude`, `longitude`, `is_default` |
| Profile address | POST | `pharmacyProfileAddress` → `…/pharmacy/profile/address` | `{ "lat": "0", "long": "0", "category": {}, "address", "region": "<city name>", "line1", "city_id" }` — called on checkout confirm **only when no saved address matches** checkout `line1` (+ city); if address field empty, uses selected city; returned `address_id`/`id` becomes checkout `user_location_id` |
| Bookings list | GET | `pharmacyBookings` / `mobileBookings(type: pharmacy)` → `…/mobile/bookings?type=pharmacy&page=&limit=` | Response `data.data[]`: `orderNo`, `orderId`, `productName`, `imageUrl`, `quantity`, `unitPrice`, `total`, `currency`, `statusV2` (list label/color; `status` is fallback), `createdAt`; paging via `page` / `limit` / `total` |
| Prescription extract | POST multipart | `AppUrls.pharmacyPrescriptionExtract` (default `http://142.86.120.73:8001/extract`) via **`ApiService`** | Form field `file` (JPEG/PNG/WEBP) and header `X-API-Key` (`AppUrls.prescriptionExtractApiKey`). No separate Dio client. A non-2xx body `detail` is shown on the scan screen. Override with `--dart-define=PRESCRIPTION_EXTRACT_BASE_URL` and `--dart-define=PRESCRIPTION_EXTRACT_API_KEY`. Response `pages` + `fields` (`type`, `date`, `doctor`, `patient`, `institute`, `location`, `medicines[]`, `tests[]`, `is_lab_report`). **UI lists `medicines` only.** Medicines are matched against pharmacy products (`display_name`) and added with the existing add-to-cart sheet (scanned image is prefilled when a prescription upload is required). Cleartext HTTP is allowed only for this host. |
| Booking detail | GET | `pharmacyBookingDetail(orderId)` → `…/mobile/bookings/{orderId}` | `data`: `publicId` (UUID used to fetch) and/or `orderId`, **`unified_order_id`** (app-bar title; never the public UUID; `orderNo` is fallback), `statusV2` (cancelled / failed / invoice; `status` is fallback), `statusTimelineV2[]` (order-status UI; `statusTimeline` is fallback; each step `label` + `completed`), `items[]`, fees, `paymentMethod`, `deliveryAddress`, `city`, optional `messageAlert` (omit UI when null/empty). **E-Invoice** shown except when status is Failed / Payment Failed; **GET** `mobileInvoice(PHARMACY, publicId)` via `DownloadInvoiceUseCase` (UUID, not `unified_order_id`); opens the in-app PDF viewer with Share / Download. Price summary hides the discount row when `discount` is 0. Order-details **feedback** UI is hidden for now. |

Products response: `{ success, message, code, data: { data: [...], page, limit, total, totalPages, hasNextPage }, timestamp }`. Each product: `product_id`, `display_name`, `image_url`, `price`, `manufacturer` (string), `category`, `prescription_required`, `generic_name`, `package_type`, `indications`, `contra_indications`, `images[]`. Parsed by `PharmacyMedicineModel` → `PharmacyMedicineEntity` (`manufacturer`, `genericName`, `prescriptionRequired`, etc.). Legacy shapes (`id`, `media.file`, nested `data.data.data`, `current_page`/`last_page`) still supported. `image_url` / `media.file` / `images[]` must be `http(s)`; `images[]` objects use `url` / `file` / `image_url` (not `toString()`). Empty or non-http URLs skip `CachedNetworkImage` via `PharmacyNetworkImage` (medication-icon placeholder) on grid, detail, cart, checkout, bookings, and add-to-cart. Grid thumbs use `memCacheWidth: 400`. When `prescriptionRequired` is true, UI shows a fully rounded `PharmacyRequiresPrescriptionBadge` pill on the product image on detail (`PharmacySelectedCard`) and grid cards (`PharmacyMedicineCard`). Grid card layout: bordered white card, product image (no grey fill), dashed divider, title (14sp), teal price + `/ packageType`, circular add-to-cart. `PharmacyQuantityStepper` plus/minus hit targets are **36×36 px**. Add-to-cart sheet shows `PharmacyPrescriptionUploadSection`; a picked or already-attached prescription shows a **photo thumbnail** (`PharmacyPrescriptionThumbnail`; PDF uses a document icon). Upload must succeed before add-to-cart. Uploaded URL stored on `PharmacyCartItemEntity.prescriptionUrl` and sent at checkout.

Cart products: each `products[]` row may nest `product { …Partner product fields… }` or be flat. Line fields: `id` (cart line), `product_id`, `quantity`, `unitPrice`/`unit_price`/`price` (unit), `line_total`/`lineTotal`/`total`/`subtotal`, `prescription_url`/`prescriptionUrl`. Mapped to `PharmacyCartItemEntity.prescriptionUrl` (server value preferred; local upload URL merged only if server blank). UI shows `displayUnitPrice` from `unitPrice`; cart totals use `lineTotal` when present. Checkout reads `delivery_charges` and `discount` from the cart API (root `data`, not `failed_payment`) and totals as `subtotal - discount + delivery_charges`. Checkout shows **Subtotal** (`state.subtotal`) above Delivery Charges, then the shared **promo code** field (`PromoCodeCubit`, `service=PHARMACY`, `amount` = cart subtotal, `isPro` from membership). Applied promo replaces the cart discount row with **Promo Discount** and sets total to API `payableAmount` + delivery (delivery is **Free** and omitted from total when validate returns `freeDelivery: true`; otherwise cart delivery charges stay as-is). Invalid shows chip + error. Promo applies only when the user submits the promo field; Confirm does not call validate. A subtotal change revalidates only while the cart still has items (empty cart after place-order does not call validate). Confirm sends `promo_code` on checkout when a code is already applied; promo state is cleared before `clearCart`. `(X%)` is shown only when cart discount is greater than 0 and no promo is applied. If the cart API sends `free_delivery_message`, checkout shows it above Subtotal. Checkout info cards use cart `messages` (`disclaimer`, `prescription_notice`, `delivery_notice`, `delivery_charges_notice`) when present.

## State

- `PharmacyCubit` — hydrates pharmacy city from prefs (no default Islamabad). Does **not** load products until a city is confirmed. `syncPharmacyCityOnOpen` / `confirmPharmacyCity` / `clearPharmacyCity`. Server-side search on search-icon tap (`submitSearch` → `display_name`); clearing the field reloads all products. Pagination (`loadMoreMedicines`), `loadProductDetail(productId)`. `PharmacyMainScreen` syncs city → picker if needed → then `loadMedicines` + `loadCart` (cart **logged-in only**). `clearHubSearch()` drops leftover search. Cart icon / add-to-cart require login. Checkout city = stored pharmacy city only (`loadCheckoutCities`). Addresses filtered to selected city. Checkout `CART_ITEMS_INVALID` surfaces `failedItems` dialog. Totals from active-cart `payment_breakdown`.

## DI

`pharmacy_injection.dart` — cities/medicines/cart/checkout/bookings use cases and `PharmacyCubit` (injects `GetPharmacyCitiesUseCase` + `PharmacyRepository` for structured error codes). Checkout payment methods use consultation `GetPaymentProvidersUseCase` (`module=pharmacy`). Prescription scan uses `ExtractPrescriptionUseCase` on `PharmacyRepository` (`ApiService.post`) and lives on `PharmacyCubit` (no separate scan cubit or Dio client).

## Routes / entry

- `AppRoutes.pharmacyMain` — pharmacy dashboard (medicines home). Extra `source` (`home` / `banner`) for `pharmacy_module`. Animated **Scan prescription** control (`PharmacyScanPrescriptionSearchButton`) floats at the bottom-right of the medicines panel when home `data.aiPrescriptionEnabled` is true (`HomeAiEnabledSession.isPrescriptionEnabled`). A white **Scan prescription** pill sits above it and bobs, same treatment as the home **Ask me anything** bubble. Tap opens `AppRoutes.pharmacyPrescriptionScan`. The search field is full width. List content keeps bottom space so the last row stays clear of the control.
- `AppRoutes.pharmacyPrescriptionScan` — uses the app `PharmacyCubit` (`prescriptionScan`). Opening the screen clears the previous scan. Idle state shows a shorter `PharmacyScanBannerCard` (`Assets.imgPharmacyScanBanner`, height `130.h`, title **Scan and Fill Your Cart**) plus an improved upload picker (empty upload area height `185.h`, inset `12`). The header cart is 22 (10 smaller than the default 32). Pick a camera/gallery photo, POST it through `ApiService` to the extract API, show **medicines only** (type/date/doctor/patient/institute/location/tests are parsed but not shown) with catalog matches and **Add to cart**. Banner hides once results are shown. Analytics (`PharmacyPrescriptionScanAnalytics`, keys on `AnalyticsEventKeys`): `pharmacy_prescription_scan_opened` / `_closed`, `_source_selected` / `_picked` (`pick_source` camera|gallery), `_started` / `_success` (`medicine_count`) / `_failed` (`error_code`), `_medicine_added`.
- `AppRoutes.pharmacy` — product description (`PharmacySelectedCard`). Generic name / manufacturer (and indications) are left-aligned even when the copy is short. Extra `selectedMedicine`; `source: search` when opened from global search.
- `AppRoutes.pharmacyCart`, `AppRoutes.pharmacyCheckout` (active Pro: `proBadge.svg` on Delivery Charges and always show Free / exclude delivery from total, including right after subscribe; otherwise `ProServiceOfferSlot` above the delivery address field), `AppRoutes.pharmacyBookingDetails` (opens with `orderId` / `publicId` for the detail GET; app bar shows **`unified_order_id`**, not the public UUID).

## Analytics

Firebase events via `PharmacyCubit` / `AnalyticsService`. Hub `source`: home services, promotional banner. `pharmacy_module` includes `city` (stored name, empty on first visit). `City_Selected` on picker confirm (`city_name`). `pharmacy_order_confirmed` adds `city` + `partner`. Global search opens product detail and logs `pharmacy_module` with `source=search`. Not logged: `source=ad` (no ad entry), `source=notification` (push opens booking details). Order confirmed sends `promo` when a checkout promo code is applied. `promo_applied` is Yes when cart discount > 0 or a promo code is applied. Booking details fire `booking_viewed` (`type=pharmacy`) via `BookingsAnalytics`; pharmacy status push/inbox may fire `pharmacy_status_changed`.

AppsFlyer (separate): `af_content_view` (`af_content_type`) on product detail success; `af_add_to_cart` (`af_content_type`, `product_id`, `product_name`, `prescription_required`) on add-to-cart success; `af_initiated_checkout` (`af_content_type`) on checkout open; `af_purchase_pharmacy` on order confirmed (`content_type`, `af_content_type`, order/user/cart/payment fields). `wellness_order`, `JazzCash Auth Code`, and `transaction_id` are sent empty until API exposes them.

## Order placed flow

After checkout confirm + order-placed dialog **View My Orders**: `pharmacyGoToOrderDetailsAfterPlace` → `home` shell with bottom **Bookings** tab and **Pharmacy** sub-tab selected (`AuthSessionRefresh.requestTabIndex` + `BookingsTabs.pharmacy`). Success dialog is non-cancelable (`barrierDismissible: false` + `PopScope(canPop: false)`); only the CTA dismisses it. Dialog copy uses `pharmacyOrderPlacedTitle` / `pharmacyOrderPlacedMessage(displayOrderNo)` / `pharmacyOrderPlacedViewOrdersCta`; `displayOrderNo` is `data.unified_order_id`. `pharmacyPopOrGoHome` on hub/details headers if the stack is empty.
