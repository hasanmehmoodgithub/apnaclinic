# Pharmacy feature

## Purpose

Browse medicines, cart, checkout, and view pharmacy order details.

Mini-cart badge shows `99+` when total quantity is greater than 99.

## Data & APIs

| Action | Method | `AppUrls` | Body |
|--------|--------|-----------|------|
| List products | POST | `pharmacyProducts` → `acs-aggregator/api/v1/mobile/partner/pharmacy/products` | `{ "page": "1", "display_name": "" }` — pass search text in `display_name` when searching; empty for browse |
| Product detail | POST | `pharmacyProductDetail` → `acs-aggregator/api/v1/mobile/partner/pharmacy/product/details` | `{ "product_id": <id>, "similar_items": true }` — product fields in `data` (`product_id`, `display_name`, `image_url`, `price`, `manufacturer`, `category`, `prescription_required`, `generic_name`, `package_type`, `indications`, `contra_indications`, `images[]`); `data.similar_items[]` for “More like” (legacy `related_items` still parsed) |
| Cart (active) | POST | `pharmacyCart` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/active` | `{}` — cart in `data` or `data.data`: `products[]` / `items[]` (each may include `prescription_url`), `booking_id` / `booking.id`, `payment_breakdown` or root `subtotal` / `delivery_charges` / `discount` / `total`, `family_members[].addresses`, optional `failed_payment.unified_order_id` |
| Add to cart | POST | `pharmacyAddToCart` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/add` | `{ "product_id": <id>, "quantity": <n> }` — both **int**; does **not** send `prescription_url` (upload is a separate API); on success, update local cart/`cartBookingId` from response (no active-cart refetch) |
| Prescription upload | POST multipart | `pharmacyPrescriptionUpload` → `…/pharmacy/prescription/upload` | Form fields: `product_id` (int) + `file` (PNG/JPEG/WEBP/PDF, max 5MB). Success `data.url` (also accepts `prescription_url` / `file_url`). Required before add-to-cart when `prescription_required` is true |
| Update cart qty | POST | `pharmacyUpdateCartQuantity` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/quantity/update` | `{ "product_id": <id>, "quantity": <n> }` — both **int**; `quantity: 0` removes the line. Success may return the full active cart (`items[]`, totals, optional `failed_payment`). On success, update local cart from response (no active-cart refetch) |
| Order checkout | POST | `pharmacyOrderCheckout` → `…/pharmacy/order/checkout` | JSON `{ "user_location_id", "payment_method" (from payment-provider `code`), "prescriptions": [{ "product_id": number, "url": string }], optional `jazz_cash_number`, `delivery_instructions`, `name`, `promo_code` }` via `PharmacyCheckoutParams`; `user_location_id` from saved/created address id; `prescriptions` from cart `prescriptionUrl`s. Success `data.unified_order_id` is shown on the order-placed dialog (not UUID `order_id`). If `status` is `PENDING_PAYMENT` and `paymentUrl` is null, skip the card WebView and show `PaymentPendingDialogWidget` (then clear cart). If `paymentUrl` is present, open `settleCardPaymentIfNeeded` before the order-placed dialog. |
| Payment providers | GET | `paymentProviders(module: pharmacy)` → `/api/v2/mobile/payment-provider?module=pharmacy` | Checkout loads providers via `GetPaymentProvidersUseCase` and shows **only** API rows (no local **Pay via Cash**). Tiles show `title` + `label.text` chip (`label.color` bg), `subtitle`, and `termsAndCondition.title` + info icon (`description` as URL or dialog). Loading uses payment-row shimmers. |
| Order abandon | POST | `pharmacyOrderAbandon` → `…/pharmacy/order/abandon` | JSON `{ "unified_order_id": int }` from cart `failed_payment.unified_order_id` (load cart first if missing; send `0` when still null). Releases cart after unpaid/failed card checkout. Called from cart/add-to-cart error dialog CTA when payment-lock message is returned |
| List addresses | POST | `pharmacyProfileAddressesList` → `…/pharmacy/profile/addresses/list` | `{}` — `data[]`: `address_id`, `label`, `recipient_name`, `recipient_phone`, `line1`, `line2`, `city_id`, `city_name`, `latitude`, `longitude`, `is_default` |
| Profile address | POST | `pharmacyProfileAddress` → `…/pharmacy/profile/address` | `{ "lat": "0", "long": "0", "category": {}, "address", "region": "<city name>", "line1", "city_id" }` — called on checkout confirm **only when no saved address matches** checkout `line1` (+ city); if address field empty, uses selected city; returned `address_id`/`id` becomes checkout `user_location_id` |
| Bookings list | GET | `pharmacyBookings` / `mobileBookings(type: pharmacy)` → `…/mobile/bookings?type=pharmacy&page=&limit=` | Response `data.data[]`: `orderNo`, `orderId`, `productName`, `imageUrl`, `quantity`, `unitPrice`, `total`, `currency`, `status` (`Confirmed` / `Failed` / `Cancelled` / …), `createdAt`; paging via `page` / `limit` / `total` |
| Booking detail | GET | `pharmacyBookingDetail(orderId)` → `…/mobile/bookings/{orderId}` | `data`: `publicId` (UUID used to fetch) and/or `orderId`, **`unified_order_id`** (app-bar title; never the public UUID; `orderNo` is fallback), `status`, `statusTimeline[]` (`label`, `completed`), `items[]`, fees, `paymentMethod`, `deliveryAddress`, `city`, optional `messageAlert` (omit UI when null/empty). **E-Invoice** shown except when status is Failed / Payment Failed; **GET** `mobileInvoice(PHARMACY, publicId)` via `DownloadInvoiceUseCase` (UUID, not `unified_order_id`); opens the in-app PDF viewer with Share / Download. Price summary hides the discount row when `discount` is 0. Order-details **feedback** UI is hidden for now. |

Products response: `{ success, message, code, data: { data: [...], page, limit, total, totalPages, hasNextPage }, timestamp }`. Each product: `product_id`, `display_name`, `image_url`, `price`, `manufacturer` (string), `category`, `prescription_required`, `generic_name`, `package_type`, `indications`, `contra_indications`, `images[]`. Parsed by `PharmacyMedicineModel` → `PharmacyMedicineEntity` (`manufacturer`, `genericName`, `prescriptionRequired`, etc.). Legacy shapes (`id`, `media.file`, nested `data.data.data`, `current_page`/`last_page`) still supported. `image_url` / `media.file` / `images[]` must be `http(s)`; `images[]` objects use `url` / `file` / `image_url` (not `toString()`). Empty or non-http URLs skip `CachedNetworkImage` via `PharmacyNetworkImage` (medication-icon placeholder) on grid, detail, cart, checkout, bookings, and add-to-cart. Grid thumbs use `memCacheWidth: 400`. When `prescriptionRequired` is true, UI shows a fully rounded `PharmacyRequiresPrescriptionBadge` pill on the product image on detail (`PharmacySelectedCard`) and grid cards (`PharmacyMedicineCard`). Grid card layout: bordered white card, product image (no grey fill), dashed divider, title (14sp), teal price + `/ packageType`, circular add-to-cart. `PharmacyQuantityStepper` plus/minus hit targets are **36×36 px**. Add-to-cart sheet shows `PharmacyPrescriptionUploadSection`; a picked or already-attached prescription shows a **photo thumbnail** (`PharmacyPrescriptionThumbnail`; PDF uses a document icon). Upload must succeed before add-to-cart. Uploaded URL stored on `PharmacyCartItemEntity.prescriptionUrl` and sent at checkout.

Cart products: each `products[]` row may nest `product { …Partner product fields… }` or be flat. Line fields: `id` (cart line), `product_id`, `quantity`, `unitPrice`/`unit_price`/`price` (unit), `line_total`/`lineTotal`/`total`/`subtotal`, `prescription_url`/`prescriptionUrl`. Mapped to `PharmacyCartItemEntity.prescriptionUrl` (server value preferred; local upload URL merged only if server blank). UI shows `displayUnitPrice` from `unitPrice`; cart totals use `lineTotal` when present. Checkout reads `delivery_charges` and `discount` from the cart API (root `data`, not `failed_payment`) and totals as `subtotal - discount + delivery_charges`. Checkout shows **Subtotal** (`state.subtotal`) above Delivery Charges, then the shared **promo code** field (`PromoCodeCubit`, `service=PHARMACY`, `amount` = cart subtotal). Applied promo replaces the cart discount row with **Promo Discount** and sets total to API `payableAmount` + delivery. Invalid shows chip + error. Confirm sends `promo_code` on checkout when applied. `(X%)` is shown only when cart discount is greater than 0 and no promo is applied. If the cart API sends `free_delivery_message`, checkout shows it above Subtotal. Checkout info cards use cart `messages` (`disclaimer`, `prescription_notice`, `delivery_notice`, `delivery_charges_notice`) when present.

## State

- `PharmacyCubit` — server-side search on search-icon tap (`submitSearch` → `display_name`); clearing the field reloads all products. Search/browse loading uses a 2-column `PharmacyMedicineCard` shimmer grid (same card layout as results). Search field stays visible during loading/error/empty. Pagination (`loadMoreMedicines`), `loadProductDetail(productId)`. `PharmacyMainScreen` calls `loadCart()` on every open (active-cart API; **logged-in only**; guests skip) and `clearHubSearch()` so a previous product search is not kept. Cart / checkout also call `loadCart()` on open. `loadCart()` sets `cartBookingId` + `cartAddresses` from `family_members[].addresses`. Cart icon / add-to-cart require login (`AuthGuard` → login). Add-to-cart: if `prescriptionRequired` and cart line has no `prescription_url`, require prescription file → `uploadPrescription` then add; if `prescription_url` already present, show attached-prescription summary with **Re-upload** (and **Keep current** to cancel); re-upload replaces the URL on add. If product already in cart, quantity-update only (keeps/`sets` `prescriptionUrl`). Add-to-cart / prescription / checkout / cart update errors show `AlertDialogCard` with the API `message` (fallback `pharmacyAddToCartFailed` / `pharmacyCheckoutFailed` / `pharmacyCartUpdateFailed`). Heart loader on upload + add + cart +/- / delete. Cart quantity stepper cannot go below 1; delete bin is a plain icon inside the quantity pill (left of minus, no circular badge) and calls `removeFromCart` → qty-update with `quantity: 0`. Checkout open: load addresses list (prefill list → profile → city). Checkout confirm: payment methods from `GET payment-provider?module=pharmacy` only (no local COD); JazzCash uses shared account sheet, Card uses shared WebView when `paymentUrl` is returned; special-instructions placeholder is `pharmacyCheckoutSpecialInstructionsHint`; Total / total amount and delivery-address input use larger type. If address empty use selected city; if checkout address matches a saved `line1` (+ city), reuse that `address_id` and **skip** create-address API; otherwise POST profile address then checkout JSON with `user_location_id` + `payment_method` + `prescriptions` from cart `prescriptionUrl`s. On success shows order-placed dialog (**Order Successfully Placed!** + `unified_order_id`, not UUID `order_id`; **View My Orders** → Bookings → Pharmacy tab), clears cart. City via shared `showSelectCityDialog` / `CitiesRepository`; totals from active-cart `payment_breakdown`.

When the API message indicates payment is still processing, cart/add-to-cart dialogs also show **Didn't pay? Cancel and return to cart** (`pharmacyAbandonUnpaidOrderCta`) → immediately POST `pharmacyOrderAbandon` with `unified_order_id` from cart `failed_payment` (refreshes active cart first; also reads that id from cart/add/qty error bodies; sends `0` if still null). ## Mocks

`PharmacyMockApi` when `MockConfig.enableMocks` is true; `getPharmacyProductsSuccessResponse` mirrors aggregator shape and filters by `display_name`. `uploadPrescriptionSuccessResponse` returns a mock `data.url`. Checkout payment providers use shared `PaymentProvidersMockApi` when consultation mocks are on.

## DI

`pharmacy_injection.dart` — medicines/cart/checkout/bookings use cases and `PharmacyCubit`. Checkout payment methods use consultation `GetPaymentProvidersUseCase` (`module=pharmacy`).

## Routes / entry

- `AppRoutes.pharmacyMain` — pharmacy dashboard (medicines home). Extra `source` (`home` / `banner`) for `pharmacy_module`.
- `AppRoutes.pharmacy` — product description (`PharmacySelectedCard`). Generic name / manufacturer (and indications) are left-aligned even when the copy is short. Extra `selectedMedicine`; `source: search` when opened from global search.
- `AppRoutes.pharmacyCart`, `AppRoutes.pharmacyCheckout`, `AppRoutes.pharmacyBookingDetails` (opens with `orderId` / `publicId` for the detail GET; app bar shows **`unified_order_id`**, not the public UUID).

## Analytics

Firebase events via `PharmacyCubit` / `AnalyticsService`. Hub `source`: home services, promotional banner. Global search opens product detail and logs `pharmacy_module` with `source=search`. Not logged: `source=ad` (no ad entry), `source=notification` (push opens booking details). Order confirmed sends `promo` when a checkout promo code is applied. `promo_applied` is Yes when cart discount > 0 or a promo code is applied. Booking details fire `booking_viewed` (`type=pharmacy`) via `BookingsAnalytics`; pharmacy status push/inbox may fire `pharmacy_status_changed`.

## Order placed flow

After checkout confirm + order-placed dialog **View My Orders**: `pharmacyGoToOrderDetailsAfterPlace` → `home` shell with bottom **Bookings** tab and **Pharmacy** sub-tab selected (`AuthSessionRefresh.requestTabIndex` + `BookingsTabs.pharmacy`). Success dialog is non-cancelable (`barrierDismissible: false` + `PopScope(canPop: false)`); only the CTA dismisses it. Dialog copy uses `pharmacyOrderPlacedTitle` / `pharmacyOrderPlacedMessage(displayOrderNo)` / `pharmacyOrderPlacedViewOrdersCta`; `displayOrderNo` is `data.unified_order_id`. `pharmacyPopOrGoHome` on hub/details headers if the stack is empty.
