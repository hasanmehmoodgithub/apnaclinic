# Pharmacy feature

## Purpose

Browse medicines, cart, checkout, and view pharmacy order details.

## Data & APIs

| Action | Method | `AppUrls` | Body |
|--------|--------|-----------|------|
| List products | POST | `pharmacyProducts` → `acs-aggregator/api/v1/mobile/partner/pharmacy/products` | `{ "page": "1", "display_name": "" }` — pass search text in `display_name` when searching; empty for browse |
| Product detail | POST | `pharmacyProductDetail` → `acs-aggregator/api/v1/mobile/partner/pharmacy/product/details` | `{ "product_id": <id>, "similar_items": true }` — product fields in `data` (`product_id`, `display_name`, `image_url`, `price`, `manufacturer`, `category`, `prescription_required`, `generic_name`, `package_type`, `indications`, `contra_indications`, `images[]`); `data.similar_items[]` for “More like” (legacy `related_items` still parsed) |
| Cart (active) | POST | `pharmacyCart` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/active` | `{}` — cart in `data` or `data.data`: `products[]` (each may include `prescription_url`), `booking_id` / `booking.id`, `payment_breakdown`, `family_members[].addresses` |
| Add to cart | POST | `pharmacyAddToCart` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/add` | `{ "product_id": <id>, "quantity": <n> }` — both **int**; does **not** send `prescription_url` (upload is a separate API); on success, update local cart/`cartBookingId` from response (no active-cart refetch) |
| Prescription upload | POST multipart | `pharmacyPrescriptionUpload` → `…/pharmacy/prescription/upload` | Form fields: `product_id` (int) + `file` (PNG/JPEG/WEBP/PDF, max 5MB). Success `data.url` (also accepts `prescription_url` / `file_url`). Required before add-to-cart when `prescription_required` is true |
| Update cart qty | POST | `pharmacyUpdateCartQuantity` → `acs-aggregator/api/v1/mobile/partner/pharmacy/cart/quantity/update` | `{ "product_id": <id>, "quantity": <n> }` — both **int**; `quantity: 0` removes the line. On success, update local cart from response (no active-cart refetch) |
| Order checkout | POST | `pharmacyOrderCheckout` → `…/pharmacy/order/checkout` | JSON `{ "user_location_id", "payment_method" (`COD` / `JAZZCASH` / `CARD`), "prescriptions": [{ "product_id": number, "url": string }], optional `jazz_cash_number`, `delivery_instructions`, `name` }` via `PharmacyCheckoutParams`; `user_location_id` from saved/created address id; `prescriptions` from cart `prescriptionUrl`s |
| List addresses | POST | `pharmacyProfileAddressesList` → `…/pharmacy/profile/addresses/list` | `{}` — `data[]`: `address_id`, `label`, `recipient_name`, `recipient_phone`, `line1`, `line2`, `city_id`, `city_name`, `latitude`, `longitude`, `is_default` |
| Profile address | POST | `pharmacyProfileAddress` → `…/pharmacy/profile/address` | `{ "lat": "0", "long": "0", "category": {}, "address", "region": "<city name>", "line1", "city_id" }` — called on checkout confirm **only when no saved address matches** checkout `line1` (+ city); if address field empty, uses selected city; returned `address_id`/`id` becomes checkout `user_location_id` |
| Bookings list | GET | `pharmacyBookings` / `mobileBookings(type: pharmacy)` → `…/mobile/bookings?type=pharmacy&page=&limit=` | Response `data.data[]`: `orderNo`, `orderId`, `productName`, `imageUrl`, `quantity`, `unitPrice`, `total`, `currency`, `status` (`Confirmed` / `Failed` / `Cancelled` / …), `createdAt`; paging via `page` / `limit` / `total` |
| Booking detail | GET | `pharmacyBookingDetail(orderId)` → `…/mobile/bookings/{orderId}` | `data`: `orderId`, `orderNo`, `status`, `statusTimeline[]` (`label`, `completed`), `items[]`, fees, `paymentMethod`, `deliveryAddress`, `city`, optional `invoiceUrl` / `messageAlert` (omit UI when null/empty). Price summary hides the discount row when `discount` is 0. |

Products response: `{ success, message, code, data: { data: [...], page, limit, total, totalPages, hasNextPage }, timestamp }`. Each product: `product_id`, `display_name`, `image_url`, `price`, `manufacturer` (string), `category`, `prescription_required`, `generic_name`, `package_type`, `indications`, `contra_indications`, `images[]`. Parsed by `PharmacyMedicineModel` → `PharmacyMedicineEntity` (`manufacturer`, `genericName`, `prescriptionRequired`, etc.). Legacy shapes (`id`, `media.file`, nested `data.data.data`, `current_page`/`last_page`) still supported. `image_url` / `media.file` / `images[]` must be `http(s)`; `images[]` objects use `url` / `file` / `image_url` (not `toString()`). Empty or non-http URLs skip `CachedNetworkImage` via `PharmacyNetworkImage` (medication-icon placeholder) on grid, detail, cart, checkout, bookings, and add-to-cart. Grid thumbs use `memCacheWidth: 400`. When `prescriptionRequired` is true, UI shows a fully rounded `PharmacyRequiresPrescriptionBadge` pill on the product image on detail (`PharmacySelectedCard`) and grid cards (`PharmacyMedicineCard`). Grid card layout: bordered white card, product image (no grey fill), dashed divider, title (14sp), teal price + `/ packageType`, circular add-to-cart. `PharmacyQuantityStepper` plus/minus hit targets are **36×36 px**. Add-to-cart sheet shows `PharmacyPrescriptionUploadSection`; a picked or already-attached prescription shows a **photo thumbnail** (`PharmacyPrescriptionThumbnail`; PDF uses a document icon). Upload must succeed before add-to-cart. Uploaded URL stored on `PharmacyCartItemEntity.prescriptionUrl` and sent at checkout.

Cart products: each `products[]` row may nest `product { …Partner product fields… }` or be flat. Line fields: `id` (cart line), `product_id`, `quantity`, `unitPrice`/`unit_price`/`price` (unit), `line_total`/`lineTotal`/`total`/`subtotal`, `prescription_url`/`prescriptionUrl`. Mapped to `PharmacyCartItemEntity.prescriptionUrl` (server value preferred; local upload URL merged only if server blank). UI shows `displayUnitPrice` from `unitPrice`; cart totals use `lineTotal` when present.

## State

- `PharmacyCubit` — server-side search on search-icon tap (`submitSearch` → `display_name`); clearing the field reloads all products. Search/browse loading uses a 2-column `PharmacyMedicineCard` shimmer grid (same card layout as results). Search field stays visible during loading/error/empty. Pagination (`loadMoreMedicines`), `loadProductDetail(productId)`. `PharmacyMainScreen` calls `loadCart()` on every open (active-cart API; **logged-in only**; guests skip). Cart / checkout also call `loadCart()` on open. `loadCart()` sets `cartBookingId` + `cartAddresses` from `family_members[].addresses`. Cart icon / add-to-cart require login (`AuthGuard` → login). Add-to-cart: if `prescriptionRequired` and cart line has no `prescription_url`, require prescription file → `uploadPrescription` then add; if `prescription_url` already present, show attached-prescription summary with **Re-upload** (and **Keep current** to cancel); re-upload replaces the URL on add. If product already in cart, quantity-update only (keeps/`sets` `prescriptionUrl`). Add-to-cart / prescription / checkout / cart update errors show `AlertDialogCard` with the API `message` (fallback `pharmacyAddToCartFailed` / `pharmacyCheckoutFailed` / `pharmacyCartUpdateFailed`). Heart loader on upload + add + cart +/- / delete. Cart quantity stepper cannot go below 1; delete bin is a plain icon inside the quantity pill (left of minus, no circular badge) and calls `removeFromCart` → qty-update with `quantity: 0`. Checkout open: load addresses list (prefill list → profile → city). Checkout confirm: payment methods shown on screen (JazzCash / Card / COD); JazzCash uses shared account sheet, Card uses shared WebView when `paymentUrl` is returned; special-instructions placeholder is `pharmacyCheckoutSpecialInstructionsHint`; Total / total amount and delivery-address input use larger type. If address empty use selected city; if checkout address matches a saved `line1` (+ city), reuse that `address_id` and **skip** create-address API; otherwise POST profile address then checkout JSON with `user_location_id` + `payment_method` + `prescriptions` from cart `prescriptionUrl`s. On success shows order-placed dialog (**Order Successfully Placed!** + order number; **View My Orders** → Bookings → Pharmacy tab), clears cart. City via shared `showSelectCityDialog` / `CitiesRepository`; totals from active-cart `payment_breakdown`.

## Mocks

`PharmacyMockApi` when `MockConfig.enableMocks` is true; `getPharmacyProductsSuccessResponse` mirrors aggregator shape and filters by `display_name`. `uploadPrescriptionSuccessResponse` returns a mock `data.url`.

## Routes / entry

- `AppRoutes.pharmacyMain` — pharmacy dashboard (medicines home).
- `AppRoutes.pharmacyCart`, `AppRoutes.pharmacyCheckout`, `AppRoutes.pharmacyBookingDetails` (opens with `orderId`, not `orderNo`; `orderNo` is display-only).

## Order placed flow

After checkout confirm + order-placed dialog **View My Orders**: `pharmacyGoToOrderDetailsAfterPlace` → `home` shell with bottom **Bookings** tab and **Pharmacy** sub-tab selected (`AuthSessionRefresh.requestTabIndex` + `BookingsTabs.pharmacy`). Dialog copy uses `pharmacyOrderPlacedTitle` / `pharmacyOrderPlacedMessage(orderNo)` / `pharmacyOrderPlacedViewOrdersCta`. `pharmacyPopOrGoHome` on hub/details headers if the stack is empty.
