1. Overview

Apna Clinic AI is a guest-capable health assistant embedded in the Flutter app. Users describe symptoms (type or voice), get streamed replies, doctor/medicine cards, slot calendars, and payment chips. Critical symptoms surface Rescue 1122.

Networking uses a dedicated ApnaClinicAiSdkClient (own Dio). It does not go through clinic ApiService HMAC / JWT interceptors.

7. Conversation ID rules

  1. Common concerns and What I can do → always a new id. The resume_open_request card is not a tile.
  2. Continue from home.resume → restore resume.conversation_id and send __resume__. Hidden once expires_at has passed. Otherwise Continue and home voice restore apnaClinicAiHistoryConversationId.
  3. Home text field → new id.
  4. History updates only after a turn is sent. Later turns in that chat keep the same id (including sign-in resume).
  5. New chat mints another id.
Rotating conversation_id mid-chat breaks triage, cart confirmations, and auth.resume.message after login.

9. Voice / audio stream

Mic tap
→
Record WAV/M4A
→
POST …/turn/audio/stream
→
Voice note + reply + TTS
  1. Mic starts ApnaClinicAiAudioRecorderService (WAV 16 kHz mono preferred, else AAC/M4A).
  2. Local STT runs in parallel for fallback text only — not shown in UI.
  3. Stop: ignore clips < 0.6s. RIFF magic → speech.wav, else speech.m4a.
  4. User bubble shows the server transcript (transcription.text) with a mic icon. Until that event arrives it says Voice note.
  5. Every assistant reply shows Play / Pause. Prefer server audio.base64; if missing, speak the reply text on-device. Voice input auto-plays; typed input does not.
  6. While audio plays, a bar above the composer also offers pause and play.
  7. Exit screen / back / new chat → stop mic, STT, and TTS.

Resiliency

  • 403 — retry up to 2× with 600 ms delay + token refresh
  • 400 / no speech — graceful reply: “I couldn’t hear any speech clearly…”
  • 502 / timeout — fall back to text stream using local STT fallbackMessage when available

10. SSE event contract

Response: text/event-stream. Frames are data: {json} separated by blank lines.

typeMeaningUI
stage Pipeline step (transcribing, tools, …) Header / thinking label
token / delta / chunk Partial reply text Stream into assistant bubble
final / done Complete turn + blocks / chips / audio Cards, TTS, stop streaming
error Turn failed Failure copy / no-speech reply

  "reply": "…",
  "status": "completed",
  "blocks": [ /* doctors, medicines, chips */ ],
  "audio": { "base64": "…", "media_type": "audio/wav" }
}

11. Cards & reply rail

  • Doctors / medicines — from blocks; images via CachedNetworkImage
  • Slots — grouped by day into calendar chips (21 / OCT)
  • Payments / quick actions — method chips send another chat message. A payment_handoff with paymentLink shows Pay now and opens that URL in the card payment web view.
  • When a slot calendar is shown, duplicate doctor cards / ISO bullets in prose are suppressed
Emergency phrases (ApnaClinicAiEmergency) show Rescue 1122 UI. Informational only — not a diagnosis.

13. Exit / stop voice

stopVoiceOnExit() cancels:

  • In-flight SSE subscription
  • Local STT (singleton — must cancel on leave)
  • Audio recorder
  • TTS playback (ApnaClinicAiAudioPlayerService.stop)

Triggered on: route dispose, home close, chat → home, New chat.
