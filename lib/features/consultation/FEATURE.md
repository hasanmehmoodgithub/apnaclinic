# Consultation feature

## Purpose

Doctor consultation category browse, doctor results, booking, and checkout.

## Routes / entry

- `AppRoutes.consultation` — category grid (`DoctorConsultationScreen`); tiles use surgery `Assets.iconsD1` / `Assets.iconsD2` background vectors on `ConsultationUiConfig.cardBackground`. Extra `source` (`home` / `banner`) for `consultancy_module`. **AI card** (from `data.ai_screening`) heading “Not sure which doctor to consult?” / subheading “Apna Clinic AI will help you find the right doctor” → **Start now!** requires login (`AuthGuard.requireLogin`); guests go to `AppRoutes.authLogin`. Shown only when `ai_screening.show` is true and `link` is non-empty. Logged-in users are asked for OS permissions listed in `ai_screening.permission` (`camera` / `microphone`), then open `AppRoutes.aiScreening` with that `link` (blocked with snackbar if denied).
- `AppRoutes.aiScreening` — in-app WebView of `ai_screening.link` (fallback `ConsultationUiConfig.apnaDoctorAiUrl` / `AppUrls.apnaDoctorAi`); no intro UI. WebView media permission requests are granted after the OS prompts. Android autoplay is enabled (`setMediaPlaybackRequiresUserGesture(false)`). iOS: Safari-like UA, eager gestures, mic requested before load; audio session is PlayAndRecord + speaker + `.voiceChat` (applied at grant and on page load; do not deactivate). App launch also activates `.playback` so WKWebView can output sound. Back (header or system) shows exit confirm dialog (`showAiScreeningExitDialog`); Exit pops, Cancel stays.
  - Analytics: `ai_chat_started` on open; `ai_chat_ended` with `call_duration` (e.g. `35s`) on confirmed Exit. AppsFlyer: same event names with `msisdn` + `call_duration` (`0s` on start).
  - On confirmed Exit, fire-and-forget **POST** `AppUrls.aiAssistantInteractions` via `RecordAiAssistantInteractionUseCase`. `session_id` is `{userId}-{uuid}` (max 64) generated when the screen opens; `started_at` is ISO 8601 with local offset; `duration_seconds` is whole seconds (0–86400). User id is not sent in the body (JWT). Failures are ignored.
- `AppRoutes.consultationDoctors` — doctor results; extra: `DoctorConsultationResultsArgs` (`selectedCategory`, `mainCategoryId`, preloaded `categoryOptions` from category grid — avoids duplicate categories API call). Book Now requires login (`AppPref.getLoginStatus()`); guests go to `AppRoutes.authLogin`. Listens to `AuthSessionRefresh.proMembershipRevision` and reloads doctors when Pro membership changes (updated fees).
- `AppRoutes.consultationCheckout` — payment screen; extra: `DoctorConsultationCheckoutArgs` (doctor, issue, selected slot, attachments, prefetched `paymentOptions`). Providers are loaded on **Get Appointment** via `GET payment-provider?module=consultation` before navigation. Checkout tiles show `title` + `label.text` chip (`label.color` bg), `subtitle`, and `termsAndCondition.title` + info icon (`description` as URL or dialog). Checkout shows `ProServiceOfferSlot` just before payment methods (Pro upsell when the user is not a member). After a successful Pro subscribe from this upsell, navigation pops back to `consultation-doctors` (`popToConsultationDoctors`) so the list can show updated prices. For an active Pro member, billing shows the **full Consultation fee** and a **Discount** line with the percent label and `proBadge.svg` only (no discount amount; tap opens the Pro sheet). Non-members still see Consultation fee as the doctor-discounted payable. Shared `PromoCodeFieldWidget` (`PromoCodeCubit`, `service=CONSULTATION`, `amount` = full `consultationFee` (not the discounted payable), `isPro` from membership), and **Promo Discount** when applied. Applied promo updates total from API `payableAmount`; invalid shows chip + error. Continue does not validate a typed code. Submits booking via `POST` `AppUrls.doctorConsultationBooking` (`multipart/form-data`).
- `AppRoutes.consultationSummary` — booking summary after payment method selection; extra: `DoctorConsultationSummaryArgs`. Doctor card shows the **selected partner logo** (`partnerLogoUrl` / known tenant fallback). Payment card uses the selected checkout provider **`iconUrl`** (`paymentMethodIconUrl`), with local JazzCash/Card assets as fallback. Billing mirrors checkout: full Consultation fee plus a **Discount** line with percent and `proBadge.svg` when Pro is applied and no promo is applied (otherwise the doctor-discounted fee); Promo Discount when a promo is applied (Pro row hidden), and total. **JazzCash** → account sheet then summary (selected msisdn). **Card** → summary with card method info (account `N/A`, profile phone as booking msisdn). Proceed submits booking; for JazzCash payments, displays the modal verification bottom sheet (`JazzCashPaymentVerificationSheet`) prompting for MPIN while the API request is in progress; other methods show the heart loader. Cancel returns to checkout. After confirm, the success dialog cannot be dismissed (back/outside tap); **View Bookings** opens Bookings → Doctor Consultation (`BookingsTabs.doctorConsultation`). Card pay with `data.blockingOrder` shows the shared pending dialog instead of the confirmed overlay; without `blockingOrder` the booking can proceed. If `blockingOrder.canAbandon` is true, the dialog also shows **Didn't pay? Cancel unpaid booking** → `POST AppUrls.doctorConsultationBookingAbandon` with `{ "order_id": publicId, "unified_order_id": 0 }` (`publicId` from `blockingOrder` then booking `data`). Dialog body uses `blockingOrder.message` when present.

## Data & APIs

- **GET** `AppUrls.doctorCategories` — `/acs-aggregator/api/v1/mobile/doctor-categories`.
  - Response `data`: `{ ai_screening, categories[] }`. Legacy `data[]` category lists still parse.
  - `ai_screening`: `link`, `show`, `permission[]` (`camera`, `microphone`).
  - `categories[]`: `id`, `title`, `iconUrl`, `rankOrder` (also accepts older `displayLabel`, `iconPath`, `displayOrder`, `isActive`).
  - Maps to `ConsultationCategoriesPageEntity` (`categories` + `aiScreening`); inactive entries filtered; sorted by `rankOrder` / `displayOrder`.
- **GET** `AppUrls.doctorConsultationDoctors(mainCategoryId, partnerId?, search?, page, limit)` — `/api/v1/mobile/doctor-consultation/doctors?mainCategoryId=&partnerId=&search=&page=&limit=`.
  - Response `data.data[]`: `id`, `publicId`, `displayName`, `specialtyName`, `yearsOfExperience`, `profileImageUrl`, `consultationFee`, `discountPercent`, `isFree`, `ratingScore` (string or number), `bio`, `education`, `qualifications`, `partner`.
  - Response `data.partners[]`: `tenantId`, `tenant` (slug e.g. `oladoc`/`mediq`/`apna-clinic`, or UUID), `logoUrl` — used for Filter sheet (`partnerId` = `tenantId`). Name from `tenant` slug when present (UUIDs ignored); known tenants fall back to local Oladoc/MedIQ logos when `logoUrl` is null.
  - Maps to `ResultsDoctorItem` via `ConsultationDoctorModel`. When a doctor's nested `partner` only has `tenantId`/`logoUrl`, name is resolved from page-level `data.partners[]` (match on `tenantId` → `tenant` slug e.g. `oladoc`). Null `yearsOfExperience` / `bio` / `education` / empty `qualifications` omit those UI lines; `ratingScore` `0.00` hides rating text. Known tenants fall back to local Oladoc/MedIQ logos when `logoUrl` is null. `apiDoctorId` keeps numeric `id` for slots API.
- **GET** `AppUrls.paymentProviders(module:)` — `/api/v2/mobile/payment-provider?module=` where `module` is `consultation` | `pharmacy` | `lab-testing` | `surgery`. `data[]`: `code`, `title`, `subtitle`, `label` `{ text, color }`, `termsAndCondition` `{ title, description }`, `logo` (legacy string `label` / `termsAndCondition`, and `name` / `iconUrl` / `isActive`, still parsed). Consultation checkout cards and lab/surgery `PaymentMethodSheet` use this shape.
- **POST** `AppUrls.doctorConsultationBooking` — `/api/v1/mobile/doctor-consultation/book-consultation` (`multipart/form-data`).
  - Fields: `doctorId`, `tenantId`, `consultationFee` (**full/original fee**, not the discounted payable), `patientId`, `patientRelation` (`self`), `slotDate`, `slotStartTime`/`slotEndTime` in 12h AM/PM (e.g. `05:00 PM`), `paymentMethod` (e.g. `JAZZCASH`), `msisdn`, `issue` (optional on the book-doctor screen; empty is sent as `N/A`), optional `promoCode` (from checkout validate), optional `attachments` file(s).
  - Multipart same as profile setup: `FormData.fromMap` with text fields + `MultipartFile.fromFile`; POST with `Content-Type: multipart/form-data` (ApiService adds boundary).
  - `tenantId` from doctor `partner.tenantId` (not JWT); `patientId` from JWT/`AppPref`; JazzCash `msisdn` from selected saved account (`ProfileSessionSync` / `AppPref` phone; default/`isDefault` pre-selected in JazzCash sheet); slot values from selected availability chip.
- **POST** `AppUrls.doctorConsultationBookingAbandon` — `/api/v1/mobile/doctor-consultation/book-consultation/abandon` JSON `{ "order_id": "<publicId>", "unified_order_id": 0 }` via `AbandonConsultationBookingUseCase`. `order_id` is booking/`blockingOrder` `publicId`. Called from the pending-payment dialog when `blockingOrder.canAbandon` is true. After success, user stays on summary and can Proceed again.
- **GET** `AppUrls.doctorConsultationBookings(page, limit)` — `/api/v1/mobile/doctor-consultation?page=&limit=` (subscriber's booked consultations).
  - Response `data`: `{ data: [], page, limit, total }`.
  - Item: `appointmentId`, `orderId`, `doctorInfo` (`doctorid`, `displayName`, `yearsOfExperience`, `profileImageUrl`, `consultationFee`, `discountPercent`, `isFree`, `education`, `specialtyName`, `ratings`, `pmdcVerified`, `partner`), `patientRelation`, `slot*`, `success`, `partnerRefNo`, optional `promoCode` (`code`, `discount`), **`totalFee`** (final payable after doctor discount + promo), `meetingLink`, `issue`, `attachments`, `doctorPerscriptions` (API typo; also accepts `doctorPrescriptions`), `patientReview` (`rating`/`review`/`date`, nullable).
  - `bookingId` resolves from `orderId` first (needed for detail GET), then `appointmentId`; `partnerRefNo` kept separately for feedback.
  - Maps to `ConsultationBookingListItemEntity` → bookings UI via `DoctorConsultationBookingMapper`. List/details show **only** `totalFee` as payable (`totalText`); original/discount rows are not shown. `success`: `PAID` → Confirmed, `PENDING_PAYMENT` → Pending, `FAILED` → Failed (list and details).
- **GET** `AppUrls.doctorConsultationBookingDetail(id)` — `/api/v1/mobile/doctor-consultation/{orderId}` — single consultation in `data` (same item shape as list). Used by Bookings **View Details** via `GetConsultationBookingUseCase`.
- **GET** `AppUrls.mobileInvoice(CONSULTATION, orderId)` — raw PDF invoice for that booking (same numeric unified `orderId` as the detail GET) via shared `DownloadInvoiceUseCase`. Opened in `LabTestReportViewerScreen` with Share / Download; not saved to Documents until the user downloads.
- **POST** `AppUrls.doctorConsultationFeedback` — `/api/v1/mobile/doctor-consultation/feedback` JSON `{ refNo, rating, review }`.
  - Used from booking details when `patientReview` is null (not cancelled); `refNo` is `partnerRefNo` (fallback booking id).
- **POST** `AppUrls.aiAssistantInteractions` — `/acs-aggregator/api/v1/mobile/ai-assistant/interactions` JSON `{ session_id, started_at, duration_seconds }`. JWT identifies the user. HMAC via existing interceptor. Called once on confirmed AI screening Exit. Requires aggregator migration 0058.
- **GET** `AppUrls.doctorConsultationSlots(doctorId, hospitalId?)` — `/api/v1/mobile/doctor-consultation/doctor/{doctorId}` (optional `?hospitalId=` when doctors list provides it).
  - Response `data.doctorInfo`: `ratings`, `pmdcVerified`, `verifiedPatientsCount`, `patientsSatisfiedPercentage`, `timeslots[]` (`date`, `slots[]` with `startTime`/`endTime` in 12h e.g. `12:40 PM`), `patientReviews` (`totalCount`, `filteredCount`, `reviews[]` with `rating`/`date`/`comment`/`patientName` — flexible keys).
  - Book-doctor screen shows Patient's Reviews under Description (first review + See More → Feedback bottom sheet). Ratings use shared `AppRoundedRatingWidget` (whole numbers without `.0`). While slots load, Verified Patients / Experience / Satisfied use shimmer cards (`isStatsLoading`).
  - Parser keeps slot times in 12h AM/PM (e.g. `03:50 PM`) for display and booking submit; legacy `data[]` with `start_time`/`end_time` still supported.
  - Missing dates between the first and last `timeslots` entry are filled as empty days (disabled in UI). First date with slots is auto-selected on load; month label reflects the selected date.
  - Uses `ResultsDoctorItem.partnerDoctorId` when present, else numeric `apiDoctorId` (`id` from doctors list).
  - Book-doctor screen uses API values only (doctors list + slots `doctorInfo`); empty or zero fields are hidden instead of hardcoded fallbacks.
- `HeaderInterceptor` adds `x-api-key` and `x-tenant-id` (when logged in) on aggregator host.

## State

- `ConsultationCubit` — loads categories + AI screening via `GetConsultationCategoriesUseCase`. Late results are ignored after the cubit closes.
- `DoctorConsultationResultsScreen` — paginated doctors via `GetConsultationDoctorsUseCase` (`page`/`limit` on scroll). Listed doctors are sorted by `ratingScore` descending (highest ratings first). Search runs on search-icon tap (or keyboard search); clear (X) appears beside the search icon when an active search is applied and reloads the full list. **Filter** opens `ConsultationSelectPartnerSheetWidget` with partners from doctors response (`data.partners`) and reloads with optional `partnerId` (`tenantId`). Active filter shows a red dot on the filter icon; sheet header shows **Clear** when a partner is selected.
- `DoctorConsultationBookDoctorScreen` — loads slots via `GetConsultationDoctorSlotsUseCase` using `ResultsDoctorItem.partnerDoctorId` or `apiDoctorId`. **Get Appointment** stays enabled whenever any time slots exist; it is disabled (faded, not tappable) only when the slots list is empty. Tap validates that a slot is selected before continuing (Issue is optional). Documents section supports up to 5 attachments (gallery/file multi-select; camera appends) with per-item delete; UI shows 1 MB per-file and 5-file limits. File picker is limited to images/PDF (`png`/`jpg`/`jpeg`/`webp`/`pdf`); audio and other types are rejected on the upload page with a snackbar. Larger or excess files are also rejected with snackbars.
- `DoctorConsultationCheckoutCubit` — uses prefetched `paymentOptions` from args when present (skips provider API); otherwise loads via `GetPaymentProvidersUseCase(module: consultation)`. Prefetch and fallback both map `label` / `termsAndCondition` onto checkout tiles. Promo validate is `PromoCodeCubit` (shared feature) on the checkout route. Submits booking via `SubmitConsultationBookingUseCase` → `PaymentInitiationResult`. Summary confirm: if `data.paymentUrl` is present, opens `AppRoutes.cardPayment` (`AndroidInterface` WebView, `allowClose: true` → AppBar **X** cancels; system back is blocked) before the success dialog. Cancel/fail shows a single `PaymentOutcomeDialogWidget` (not a snackbar). If `data.blockingOrder` is present, skip the WebView and show shared `PaymentPendingDialogWidget` (CTA **View My Bookings**; app copy, or `blockingOrder.message` when present). If `blockingOrder.canAbandon`, secondary CTA calls `AbandonConsultationBookingUseCase`. If `blockingOrder` is absent, the booking can proceed. JazzCash Continue opens `DoctorConsultationJazzCashAccountsSheetWidget` (Select Account only — no JazzCash info tile; reads phones from `ProfileSessionSync` / prefs, no GET on open; default pre-selected). **Add Account** opens shared `AddAccountScreen` (`AddAccountLaunchSource.consultationCheckout`); on save, sheet refreshes via `GetAccountsListUseCase` and selects the new number. Same sheet is reused by lab checkout and surgery booking pay.
- `DoctorConsultationBookingsCubit` (bookings tab) — loads paginated bookings via `GetConsultationBookingsUseCase`.
- Booking details — loads single booking via `GetConsultationBookingUseCase`; submits feedback via `SubmitConsultationFeedbackUseCase`.

## Analytics

Firebase via `ConsultationAnalytics` / `AnalyticsService`. Hub `source`: home services, promotional banner. Global search opens book-doctor and logs `consultancy_module` with `source=search`. Not logged: `source=ad` (no ad entry), `source=notification` (push opens booking details). `doctor_consultation_booked` fires only after successful payment (not on fail or pending blocking order) and sends `promo` when a promo code is applied. `promo_applied` is Yes when checkout discount > 0 or a promo code is applied.

AppsFlyer (separate): `consultancy_module` (`source` `home` / `banner`) only when the category hub opens. Category open, doctor search, partner filter, and book-doctor from global search stay on Firebase only. `doctor_profile` (`doctor_id`, `doctor_name`, `category`, `timeslot`) on profile click/screen/confirm; `af_purchase_consultation` on booked with consultancy content types + booking/user/doctor/payment fields (`wellness_order` empty; `transaction_id` from `publicId` when present). No Meta/TikTok `fb_content_type` on AF.
