Dependency Injection Guide

Quick Start: Adding a New Feature

Step 1: Create Feature Injection File

Create lib/features/[feature_name]/[feature_name]_injection.dart:

import '../../core/di/dependency_injection.dart';
import '../../core/network/api_client.dart';
import 'data/data_sources/[feature]_remote_data_source.dart';
import 'data/data_sources/[feature]_remote_data_source_impl.dart';
import 'data/repositories/[feature]_repository_impl.dart';
import 'domain/repositories/[feature]_repository.dart';
import 'domain/use_cases/[use_case_1].dart';
import 'domain/use_cases/[use_case_2].dart';
import 'presentation/cubit/[feature]_cubit.dart';

void init[Feature]Injector() {
  sl.registerLazySingleton<[Feature]RemoteDataSource>(
    () => [Feature]RemoteDataSourceImpl(sl<ApiClient>()),
  );

  sl.registerLazySingleton<[Feature]Repository>(
    () => [Feature]RepositoryImpl(sl<[Feature]RemoteDataSource>()),
  );

  sl.registerLazySingleton<[UseCase1]>(
    () => [UseCase1](repository: sl<[Feature]Repository>()),
  );

  sl.registerLazySingleton<[UseCase2]>(
    () => [UseCase2](repository: sl<[Feature]Repository>()),
  );

  sl.registerFactory<[Feature]Cubit>(
    () => [Feature]Cubit(
      useCase1: sl<[UseCase1]>(),
      useCase2: sl<[UseCase2]>(),
    ),
  );
}

Step 2: Register in Main DI File

Add import and call the injector in lib/core/di/dependency_injection.dart:

import '../../features/[feature_name]/[feature_name]_injection.dart';

Future<void> initDependencyInjection() async {
  await _initCore();
  init[Feature]Injector();
}

Step 3: Use in UI

import 'package:flutter_bloc/flutter_bloc.dart';
import '../../../../core/di/dependency_injection.dart';
import '../cubit/[feature]_cubit.dart';

BlocProvider(
  create: (context) => sl<[Feature]Cubit>(),
  child: YourWidget(),
)

Registration Types

Method Behavior Use For
registerLazySingleton<T> Creates instance only when first accessed, then reuses it Repositories, Data Sources, Use Cases, Services, Singletons
registerFactory<T> Creates new instance every time it's accessed Cubits, BLoCs, ViewModels (stateful widgets need fresh instances)
registerSingleton<T> Creates instance immediately at registration time Services that need immediate initialization

Examples

sl.registerLazySingleton<ApiClient>(() => ApiClient());

sl.registerFactory<LoginCubit>(() => LoginCubit(useCase: sl<LoginUseCase>()));

sl.registerSingleton<AppDatabase>(AppDatabase());

Registration Order

Always register dependencies in this order:

  1. Data Sources (RemoteDataSource, LocalDataSource)
  2. Repositories (depends on Data Sources)
  3. Use Cases (depends on Repositories)
  4. Cubits/BLoCs (depends on Use Cases)

Common Patterns

Adding a Service

sl.registerLazySingleton<MyService>(() => MyService());

Adding a Repository with Local Data Source

sl.registerLazySingleton<LocalDataSource>(() => LocalDataSourceImpl());
sl.registerLazySingleton<Repository>(
  () => RepositoryImpl(
    remoteDataSource: sl<RemoteDataSource>(),
    localDataSource: sl<LocalDataSource>(),
  ),
);

Conditional Registration

if (!sl.isRegistered<MyService>()) {
  sl.registerLazySingleton<MyService>(() => MyService());
}

Resolving Dependencies

final cubit = sl<MyCubit>();
final useCase = sl<MyUseCase>();
final repository = sl<MyRepository>();

Best Practices

  • ✅ Register dependencies in dependency order (Data Sources → Repositories → Use Cases → Cubits)
  • ✅ Use sl<T>() to resolve dependencies
  • ✅ Keep feature injection files separate for better organization
  • ✅ Use registerFactory for Cubits/BLoCs to ensure fresh instances per widget
  • ✅ Use registerLazySingleton for stateless services and repositories
  • ✅ Check registration with sl.isRegistered<T>() if needed
  • ✅ Keep core dependencies in _initCore() and feature dependencies in separate injectors

Troubleshooting

Error: "Object/factory with type X is not registered"

  • Make sure you registered the dependency before using it
  • Check that you called the injector function in initDependencyInjection()
  • Verify the registration order (dependencies must be registered before dependents)

Error: "Circular dependency detected"

  • Review your dependency graph
  • Consider using lazy initialization or restructuring dependencies

Multiple instances created

  • Use registerLazySingleton instead of registerFactory for services
  • Use registerFactory only for Cubits/BLoCs that need fresh instances
💡 Tip: Keep your DI registrations modular — each feature should manage its own injection file for easy maintenance and scalability.
