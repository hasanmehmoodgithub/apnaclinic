How it works in this app

Screens and Cubits do not compute HMAC. AuthCubit.requestOtp still calls ApiService.post as before. A Dio interceptor stamps five headers onto every acs-aggregator and acs-auth request before it leaves the device.

No feature-level signing JSON + GET + multipart Refresh Dio signed CMS / notifications skipped Log name: HmacSigning

Startup

  1. HmacSecretStore.initialize() in dependency_injection.dart
  2. Android/iOS secrets loaded (defaults baked in, like MOBILE_API_KEY) and copied to Keystore / Keychain
  3. Same store injected into ApiService and AuthInterceptor

Every API call

1. FeatureApiService get/post
2. HeaderInterceptorDevice, x-api-key, tenant
3. AuthInterceptorBearer JWT if logged in
4. HMAC interceptorFive headers + freeze JSON
5. Logger / ChuckerYou inspect the signed request
6. Server guardMatch signature, nonce, clock

What is signed

hmacBackendFor(uri) looks at the URL path only.

Path containsSecretSigned?
acs-aggregator (cities, lab, pharmacy, consultations, …)Platform android/ios keyYes — guest and logged-in
acs-auth (OTP, verify, refresh, logout, profile phones, …)Same platform keyYes
acs-cmsbe, notifications, dummyjson—No

HMAC does not replace login. Guest aggregator still sends x-api-key. Logged-in calls still send Authorization. Wire path includes the gateway prefix, e.g. /acs-auth/api/v1/auth/otp/generate.

Worked example — request OTP

This is the call that returned missing_headers when the interceptor skipped signing.

Login tap
  → AuthCubit.requestOtp
  → ApiService.post(AppUrls.requestOtp, { msisdn, channel: SMS })
  → path contains acs-auth → userAuth
  → x-key-id = ios (or android)
  → digest = SHA-256 of jsonEncode(body)
  → canonical string (six lines)
  → x-signature = HMAC-SHA256(platform secret, canonical)

{"msisdn":"923015077202","channel":"SMS"}
Console must show Signed userAuth POST /acs-auth/api/v1/auth/otp/generate and Chucker must list all five x-* HMAC headers. If Chucker has only device headers + x-api-key, the interceptor skipped — that is missing_headers.

Secrets

Keys are per platform. Aggregator and user-auth share the same secret for the running OS. Optional HMAC_AGGREGATOR_SECRET / HMAC_AUTH_SECRET override only if backend later splits them.

x-key-idDart define
androidHMAC_ANDROID_SECRET (baked-in default)
iosHMAC_IOS_SECRET (baked-in default)

Resolution order

  1. Per-service override (if set)
  2. In-memory value from initialize()
  3. Compile-time fromEnvironment / default
  4. Hardcoded platform fallback (covers hot-reload empty memory)
flutter run --dart-define-from-file=hmac.keys.json
GetIt keeps one store for the whole session. After changing secret code, use hot restart (or stop/run), not only hot reload. hmac.keys.json is gitignored. Debug logs never print the secret.

Refresh and retries

  • Token refresh uses a second Dio with the same HMAC interceptor (user-auth must be signed in enforce).
  • JWT 401 retry strips old HMAC headers so a new nonce is minted (reuse → nonce_replayed).
  • Guest OTP 401 does not refresh (no refresh token). HMAC 401 on a logged-in call may try refresh; that will not fix a bad signature.

401 reasons

Backend HMAC_MODE=enforce returns a generic 401. The reason is in error.message for debug only — do not branch UI on it.

Server reasonIn this app
