2. Startup flow

Do not block the first frame on a network fetch. Production activates the cached template (disk, no billable fetch), then fetches in the background.

4. How Firebase Remote Config works

Remote Config is a key/value template in the Firebase console. The SDK keeps a copy on the device. Reading a value is local. Only fetch / fetchAndActivate talks to Google and counts against quota.

1. Defaults Compiled into the app. Always available on first install and when Firebase is down.
2. Fetch Downloads the template if the minimum interval has elapsed (12 hours in production).
3. Cache Stored on disk. Next cold start can activate() this without a network call.
4. Activate + getString Makes fetched keys live. getString('api_base_url') is not billed.

Console

api_base_url String https://pharmacy.apnaclinic.com.pk

Optional Firebase condition: production package / bundle only (com.apna.clinic.android / com.apna.clinic.ios) so a debug build on the same project cannot pick up the override.

5. Fail defaults — what happens when RC fails

The app must still call the API. Fetch failure is expected (offline, timeout, Spark throttle, bad console value).

EventWhat the app uses
Firebase init failsFlavor production URL. Skip Remote Config entirely.
Fetch timeout / no networkLast-good if present, else flavor URL. Background fetch can retry later.
Empty / non-HTTPS / unknown hostReject. Fall back to last-good, then flavor URL.
Spark throttle after grace periodSDK cannot download a new template. Cached / default values keep working.
Host would change mid-sessionPrefer apply on next cold start so HMAC signing stays on one host.

A wrong console URL can break login for every production user. Use the allowlist and roll out 10% → 50% → 100%.

6. Free quota (not “users”)

Remote Config is billed per fetch request per day, not monthly active users. Spark (no-cost) includes 100,000 fetches/day.

If each device fetches…Approx. DAU inside free cap
Once per day~100,000 daily active devices
Twice per day (12h interval, two opens)~50,000 daily active devices
  • Reading cached values does not count.
  • Production minimum fetch interval: 12 hours (24–48h is fine for a stable host).
  • Do not fetch on every screen.
  • Spark overage: 30-day grace, then extra fetches are throttled; users keep last-good / in-app default.
  • Blaze: first 100k/day still free, then pay per extra fetch (no throttle).
